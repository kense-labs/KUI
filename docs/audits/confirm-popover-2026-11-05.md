# ConfirmPopover 完成态圆角修复

2026-11-05。用户截图中的绿色「已完成」进度条覆盖了按钮原有圆角。

## 定位与依据

`nav::button` 的默认外轮廓已读取 `surface_radius`（8px）；问题在 `ConfirmPopover` 的绝对定位填充层：自身使用直角背景，GPUI 的 `overflow_hidden` 只提供矩形内容裁切，没有将子元素裁成父元素的圆角。

参考[官方公开页面](https://uiarc.dev/components/confirm-popover)的进度与反色文案说明；该组件为 Pro，公开 `/r/confirm-popover.json` 返回 HTTP 404，不能声称读到了它的私有实现。8px 轮廓遵循 KUI `DESIGN.md`。本次修正原有 Rust 绘制，不改变尺寸、请求接口、成功停留时间或重试行为。

## 修改

将圆角底片保持在按钮完整尺寸，在其外部使用进度宽度的矩形裁切。这样进度前沿仍为直线，最外侧四角与按钮一致，反色文字和底片一起裁切，部分匹配、重试与成功不会因文字变化而错位。桌面、Web 和复制安装共用同一 Rust 源码。

## 验证

扩展既有 GPUI 行为回归：输入不匹配不得提交；过期回执不得改变状态；失败后重试只发出一个新序号；成功时填充与按钮实际边界相同，检查最终绘制 quad 的四个圆角均为 8px。该用例已通过。

WASM 库/Web 检查、release 构建、注册表生成与预览哈希校验、网站输入与构建检查均通过。最终本地预览版本 `9d0dc8fca5926b53c04d`。

真实浏览器从「移除」→「确认」进入处理中，再进入「已完成」。连续截取14张浏览器画面，成功填充的四角已呈8px圆角，未再盖成直角长条。成功实拍为 `/private/tmp/kui-confirm-result-13.jpg`，示例随后已复位供用户继续操作。该短采样用于确认这次圆角修复，不代表全站帧率或完整动效对齐验收。

仅本地修改，不推送或发布。
